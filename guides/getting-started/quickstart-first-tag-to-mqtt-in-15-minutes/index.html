Quickstart: Read Your First Tag over MQTT in 15 Minutes

Tutorial·Audience: Administrators and integrators·Read time: 10 min read

In this quickstart, you configure the reader's Control and Tag Data 1 interfaces to use MQTT, configure the operating mode, start RFID inventory, and receive your first tag observation in an MQTT client.

  • Control – Send commands to the reader and receive command responses.
  • Tag Data 1 – Receive RFID tag observations from the reader.
note

Configure, preview, and publish each interface separately, even when both interfaces use the same broker.

Before You Begin​

  • Complete the reader installation, sign in to the web console, and configure the regulatory region, date, and time.
  • Have a compatible RFID test tag and a configured antenna in the read area.
  • Have access to an MQTT broker and an MQTT client, such as MQTTX, that can publish and subscribe to topics. Both the reader and the client must be able to reach the broker.
  • Obtain the broker connection details, credentials, and certificates, if required.
  • Ensure that the MQTT clients have the required permissions to publish and subscribe to the configured topics.

Step 1: Configure the Control Interface​

Configure the Control interface to receive commands and publish command responses through the MQTT broker.

  1. In the reader web console, open Settings > Endpoint and select Control.

  2. Set Endpoint Type to MQTT and enter the broker connection details.

  3. On the Topic tab, configure the Control command and response topics.

    Use your broker settings. The following example uses unencrypted TCP on a trusted test network.

    SettingExample value
    Endpoint TypeMQTT
    Server192.168.0.10
    Port1883
    ProtocolTCP
    Client IDreader-01-control
    Command Topic (reader subscribes)readers/reader-01/control/command
    Response Topic (reader publishes)readers/reader-01/control/response

  4. Configure certificates, if required.

  5. Select Preview to review the settings and select Publish.

  6. Confirm that the Control interface shows connected.

For field descriptions and screenshots, see Connect to an MQTT Broker.

Step 2: Configure the Tag Data Interface​

Configure the Tag Data 1 interface to publish RFID tag observations to the MQTT broker.

  1. In Settings > Endpoint, select Tag Data 1.

  2. Set Endpoint Type to MQTT and enter the broker connection details.

  3. On the Topic tab, configure the Tag Data publish topic.

    Use the following example settings:

    SettingExample value
    Endpoint TypeMQTT
    Server192.168.0.10
    Port1883
    ProtocolTCP
    Client IDreader-01-data1
    Publish Topicreaders/reader-01/data/tags1

  4. Configure certificates, batching, and retention as needed.

  5. Select Preview, review the settings for Tag Data 1, and select Publish.

  6. Confirm that the Tag Data 1 interface shows connected.

note

Use a different MQTT client ID for each active connection to the same broker. For a secure broker connection, use its TLS port and configure the required credentials and certificates.

For detailed configuration instructions, see Connect to an MQTT Broker.

Step 3: Connect the MQTT Client and Subscribe to Topics​

  1. Open your MQTT client.
  2. Create a connection using the broker connection details configured in Steps 1 and 2.
  3. Enter a unique client ID, such as mqttx-quickstart.
  4. Connect to the MQTT broker.
  5. Subscribe to the Control response and Tag Data topics before sending commands. Select JSON as the payload format and turn off Retain when publishing commands.

Use the following table to identify the topics and their purpose.

TopicExampleMQTT client action
Control commandreaders/reader-01/control/commandPublish commands
Control responsereaders/reader-01/control/responseSubscribe to receive command responses
Tag Datareaders/reader-01/data/tags1Subscribe to receive tag observations

Use the actual topic names configured for your deployment.

If the Control and Tag Data interfaces use different brokers, create a separate MQTT client connection to each broker.

Optional: Check the reader version through the Management interface

If you also configured the Management interface for MQTT, you can verify it by requesting version information. Connect to its broker and subscribe to the configured Management response topic first. For example, publish to readers/reader-01/management/command and receive the response on readers/reader-01/management/response.

Request:

{
"command": "get_version",
"command_id": "req-version-01",
"payload": {}
}

Example response:

{
"command": "get_version",
"command_id": "req-version-01",
"response": "success",
"payload": {
"readerApplication": "2.0.7-5",
"radioFirmware": "2.1.57.0"
}
}

The example response is shortened. Version values and other fields depend on the reader. See the get_version reference.

Step 4: Start Inventory and Read a Tag​

Configure the Operating Mode​

Publish the following set_mode request to the Control command topic.

This example selects SIMPLE mode, uses antenna 1, and requests the antenna number in tag reports. Use the antenna port or beam appropriate for your reader and installation.

Request:

{
"command": "set_mode",
"command_id": "req-set-mode-01",
"payload": {
"type": "SIMPLE",
"antennas": [
1
],
"tagMetaData": [
"ANTENNA"
]
}
}

Example response on the Control response topic:

{
"command": "set_mode",
"command_id": "req-set-mode-01",
"response": "success",
"payload": {}
}

Verify the Operating Mode​

To verify the configured operating mode, publish the following get_mode request to the Control command topic.

Request:

{
"command": "get_mode",
"command_id": "req-get-mode-01",
"payload": {}
}

Example response on the Control response topic:

{
"command": "get_mode",
"command_id": "req-get-mode-01",
"response": "success",
"payload": {
"type": "SIMPLE",
"antennas": [
1
],
"tagMetaData": [
"ANTENNA"
]
}
}

The actual response can include additional settings. Confirm that the operating mode and antenna configuration are suitable before starting inventory.

For more information, see the MQTT set_mode and get_mode command references.

Start Inventory​

  1. In your MQTT client, publish the following start request to the Control command topic.

    Request:

    {
    "command": "start",
    "command_id": "req-start-01",
    "payload": {
    "doNotPersistState": true
    }
    }

  2. Check the Control response topic for the matching command_id.

    Example response:

    {
    "command": "start",
    "command_id": "req-start-01",
    "response": "success",
    "payload": {}
    }

  3. Confirm that the command response indicates success.

The reader starts RFID inventory.

For more information, see the MQTT start command reference.

Receive Tag Data​

  1. Place the RFID test tag within the antenna's read range.
  2. Monitor the subscribed Tag Data topic in your MQTT client.
  3. Verify that a tag observation is received.

Example tag observation:

{
"type": "SIMPLE",
"timestamp": "2019-08-24T14:15:22Z",
"data": {
"antenna": 1,
"eventNum": 1,
"format": "epc",
"idHex": "3005fb63ac1f3681ec880468"
}
}
FieldDescription
typeType of tag observation generated by the reader.
timestampTimestamp associated with the tag observation.
data.antennaAntenna that detected the tag.
data.eventNumEvent sequence number.
data.formatFormat of the reported tag identifier.
data.idHexTag identifier in hexadecimal format.

The tag identifier, timestamp, and other fields vary depending on the tag and reader configuration.

For more information, see the Tag Data Events reference.

Step 5: Stop Inventory​

  1. Publish the following stop request to the same Control command topic.

    Request:

    {
    "command": "stop",
    "command_id": "req-stop-01",
    "payload": {}
    }

  2. Check the Control response topic for the matching command_id.

    Example response:

    {
    "command": "stop",
    "command_id": "req-stop-01",
    "response": "success",
    "payload": {}
    }

  3. Confirm that the reader stops inventory and no new RFID tag observations are generated.

Previously buffered tag observations may still arrive after inventory stops, depending on the batching and retention configuration.

If a command response indicates failure, check its payload for error details.

For more information, see the MQTT stop command reference.

note

Use a unique command_id for each command to correlate requests with their corresponding responses.

You have successfully configured the reader to communicate over MQTT, started RFID inventory, and received your first RFID tag observation.

Alternative: Configure and Operate the Reader Using APIs​

You can also perform the interface configuration and RFID operations covered in this quickstart programmatically without using the reader web console.

This approach is useful for automated reader provisioning, headless deployments, and application integration.

The following table lists the REST API operations and equivalent MQTT commands.

OperationREST APIMQTT Command
AuthenticateGET /cloud/localRestLoginConnect to the broker using its authentication settings (Step 3).
Configure MQTT interfacesPUT /cloud/cloudConfigset_importCloudConfig
Check the reader version (optional)GET /cloud/versionget_version
Configure the operating modePUT /cloud/modeset_mode
Verify the operating modeGET /cloud/modeget_mode
Start RFID inventoryPUT /cloud/startstart
Stop RFID inventoryPUT /cloud/stopstop

Using the Local REST API​

To perform the quickstart using the local REST API:

  1. Send GET /cloud/localRestLogin over HTTPS using HTTP Basic authentication with your reader administrator credentials. On success, use the token in message as Authorization: Bearer <token> on subsequent REST requests.
  2. Configure the required MQTT interfaces using PUT /cloud/cloudConfig.
  3. Verify that the configured interfaces are connected to the MQTT broker.
  4. Send PUT /cloud/mode with the mode settings shown in Step 4. For the REST request body, use the JSON object inside payload.
  5. Verify the operating mode using GET /cloud/mode.
  6. Connect your MQTT client to the broker and subscribe to the configured Tag Data topic.
  7. Start RFID inventory using PUT /cloud/start.
  8. Place the test tag within the antenna's read range and verify the received tag observation.
  9. Stop RFID inventory using PUT /cloud/stop.

For authentication requirements, request parameters, payload examples, and response details, see the REST API Reference.

Using MQTT Commands​

To configure the MQTT interfaces programmatically, the Management interface must already be configured and connected to an MQTT broker.

  1. Connect your MQTT client to the broker used by the Management interface.
  2. Subscribe to the configured Management response topic.
  3. Publish set_importCloudConfig to the Management command topic to configure the Control and Tag Data 1 interfaces.
  4. Verify that both interfaces are connected to their configured brokers.
  5. Follow Step 3 through Step 5 to configure the operating mode, start inventory, receive tag observations, and stop inventory.

For command parameters, payload examples, and response details, see the MQTT API Reference.

Troubleshooting​

If you encounter issues during this quickstart, check the following:

IssueRecommended action
MQTT client cannot connect to the broker.Verify the broker address, port, credentials, and network connectivity.
Reader interface shows disconnected.Verify the endpoint configuration, broker availability, credentials, and certificates.
No command response is received.Verify the Control command and response topics, MQTT permissions, and interface connection status.
Command response indicates failure.Check the response payload for error details.
RFID inventory fails to start.Verify the regulatory region, operating mode, and antenna configuration.
Inventory starts but no tag data is received.Verify the Tag Data interface connection, topic subscription, antenna configuration, and tag position.
MQTT connection disconnects unexpectedly.Ensure that each active connection to the same broker uses a unique client ID.
Tag observations contain incorrect timestamps.Verify the reader's date, time, and time synchronization settings.
