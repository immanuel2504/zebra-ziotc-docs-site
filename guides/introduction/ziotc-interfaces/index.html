ZIoTC Interfaces

Explanation·Audience: Administrators, integrators, and developers·Read time: 4 min read

Zebra IoT Connector (ZIoTC) provides four types of interfaces that enable applications to configure and manage the reader, control RFID operations, and receive tag observations and reader events.

Each interface can be configured independently to communicate with its own supported endpoint, allowing applications to integrate with the reader in cloud, on-premises, or hybrid deployments.

Figure 1: Communication between external applications and the reader through ZIoTC interfaces.

Interface Overview​

The following table describes the purpose, communication model, and supported communication methods for each interface.

InterfacePurposeCommunication ModelCommunication Methods
ManagementConfigure and administer the reader.Command and responseMQTT, Local REST API
ControlControl RFID operations.Command and responseMQTT, Local REST API
DataDeliver tag observations and supported BLE scan data.Asynchronous data deliveryMQTT, HTTP POST
Management EventsReport reader health and operational events.Asynchronous event deliveryMQTT, HTTP POST

Available communication methods depend on the reader model, firmware, and supported endpoint types.

Management Interface​

The Management interface enables applications to configure, administer, and monitor the reader.

Typical operations include:

  • Configuring network and time settings.
  • Retrieving reader information, status, and configuration.
  • Managing certificates.
  • Updating firmware.
  • Configuring heartbeat and event reporting settings.
  • Configuring communication endpoints.

The application sends a management command or request, and the reader returns the corresponding response.

Control Interface​

The Control interface enables applications to control RFID operations and configure how the reader interacts with RFID tags.

Typical operations include:

  • Configuring the RFID operating mode.
  • Starting and stopping RFID inventory.
  • Configuring tag reading behavior.
  • Performing supported tag memory operations.

The application sends a control command or request, and the reader returns the corresponding response. Tag observations generated during RFID operations are delivered separately through the Data interface.

Data Interface​

The Data interface delivers RFID tag observations and, on supported readers, Bluetooth Low Energy (BLE) scan data to external applications.

A tag observation can include information such as:

  • Electronic Product Code (EPC).
  • Timestamp.
  • Antenna identifier.
  • Signal strength.

The reader provides two configurable data interfaces:

InterfacePurpose
Tag Data 1Delivers observations to the first configured data endpoint.
Tag Data 2Delivers observations to the second configured data endpoint.

Both interfaces can be configured independently to deliver observations to the same or different destinations.

Management Events Interface​

The Management Events interface enables applications to monitor the reader's health and operational status.

Supported events can include:

  • Heartbeats containing reader health information.
  • General-purpose input/output (GPIO) events.
  • Warnings and errors.
  • On-reader application events.

Unlike the Management interface, which returns responses to requests, the Management Events interface sends events asynchronously without requiring an individual request from the application.

Event reporting settings, such as heartbeat intervals and supported warning thresholds, can be configured through the Management interface.

Interface Communication​

ZIoTC uses two communication models based on the purpose of the interface.

Command and Response Communication​

The Management and Control interfaces use command-response communication.

Communication MethodDescription
MQTTThe application publishes a command to the configured command topic. The reader processes the command and publishes the response to the configured response topic.
Local REST APIThe application sends an HTTP request to the reader and receives the result in the HTTP response.

Asynchronous Data and Event Communication​

The Data and Management Events interfaces deliver observations and events without requiring an individual request for each message.

Communication MethodDescription
MQTTThe reader publishes observations or events to a configured topic. Applications subscribe to the topic to receive messages.
HTTP POSTThe reader sends observations or events to a configured HTTP endpoint.

How the Interfaces Work Together​

Consider a warehouse application that uses a fixed RFID reader installed at a dock door to track incoming shipments.

  1. The application uses the Management interface to configure the reader, data endpoints, and heartbeat settings.
  2. The application uses the Control interface to configure the operating mode and start RFID inventory.
  3. As tagged items pass through the dock door, the reader delivers tag observations through the Data interface.
  4. The reader reports health information, heartbeats, warnings, and errors through the Management Events interface.
  5. When the operation is complete, the application uses the Control interface to stop RFID inventory.
